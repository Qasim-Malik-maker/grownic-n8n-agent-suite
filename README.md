# Grownic 10-Agent Suite

**The importable agents are in `workflows/`.** Version **1.1.1** contains 10 business workflows and 6 supporting workflows, executable source, PostgreSQL migrations, Docker Compose, fixtures, tests and a Vapi assistant configuration. Target: n8n **2.38.7**.

Start with **01 Speed to Lead**, **05 Follow Up**, **06 Appointment Setting** or **04 Voice Receptionist** for a local service business. Each customer needs its own configuration, database and provider accounts. The example prices and content are synthetic.

## Import and test

1. Install Node.js 22+ and Docker Desktop / Docker Compose.
2. In the cloned or extracted folder run `npm ci`, `npm run build`, then `npm run configure`. The build creates the combined CLI import file.
3. Run `docker compose up -d`. Open `http://localhost:5678` and create your n8n owner account.
4. Run `node scripts/import.mjs --publish-test`, then `docker compose restart n8n`.
5. Run `npm run smoke`. It checks all ten production webhook paths with synthetic input and repeats each request to verify replay behavior.
6. Open `http://localhost:5678/webhook/grownic/review/v1` and authenticate with the local review credentials generated by `npm run configure`. Those credentials are not stored in this repository. In test mode, approval changes an action to **simulated**.

For an existing n8n installation, import the individual JSONs through **Import from file** and configure the named credentials. Install the two SQL migrations in a dedicated PostgreSQL 16+ database, load `config/client.json` into `grownic.settings`, and assign the PostgreSQL credential to each workflow. The shared workflows are required. See `docs/DEPLOY.md` for exact setup and service-specific requirements.

`all-workflows.json` is the generated combined **CLI import** file. The GitHub package stores it as `all-workflows.json.gz`; run `gzip -dk all-workflows.json.gz` or `npm run build` after cloning. The n8n editor expects one workflow JSON at a time. No credential secrets are included in this delivery.

## What is included

| File | Business function |
|---|---|
| `01-speed-to-lead.json` | Validate enquiries, record contact, prepare immediate email/SMS acknowledgement |
| `02-lead-generation.json` | Search public company pages, require literal email evidence, deduplicate and queue CRM insertion |
| `03-quote.json` | Parse service requests, calculate approved prices/tax, attach an actual PDF estimate |
| `04-voice.json` | Vapi tools for service lookup, availability, booking and callback; call summary capture |
| `05-follow-up.json` | Enroll consenting contacts and process replies/opt-outs/bookings/bounces |
| `06-appointment.json` | Live slots, confirmed booking request, ownership-checked cancel/reschedule |
| `07-recruitment.json` | Extract requirement evidence and queue an interview invitation for human decision |
| `08-content.json` | Repurpose source text into reviewed posts; LinkedIn and visual platforms stay manual |
| `09-marketing.json` | Read Meta performance, draft test proposals, optionally create approved PAUSED ads |
| `10-support.json` | Select approved FAQ answers, return verbatim answers, record human handoffs |

Shared workflows: **80** durable delivery worker, **81** follow-up/reminder scheduler, **82** approval console and health, **83** verified provider events, **84** approved knowledge ingest, **90** error log.

The included flow diagrams describe the implemented behavior. Read `docs/AGENTS.md` for inputs, boundaries and acceptance checks. The package is an importable implementation for customer configuration and testing; live credentials, phone routing, sender verification and client data remain installation steps. It is not a claim of measured commercial results or superiority over every competing product.

The release was imported into an isolated n8n 2.38.7 instance and all ten synthetic webhook paths completed successfully with idempotent replays. See `docs/VALIDATION.md` for the exact validation boundary.
